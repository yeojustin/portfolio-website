Live Binance Order Book & OBI Dashboard

The Project Goal

The goal of this project is to build an high-fidelity, institutional-grade market data pipeline that clones a live cryptocurrency trading order book directly from Binance onto a local machine. By stitching two independent data feeds together perfectly, the system eliminates data delay and accurately calculates Order Book Imbalance (OBI)—a vital mathematical indicator used by high-frequency trading algorithms to spot immediate buy or sell pressure before price changes happen.


Core Trading Terms Explained

To understand this system, you must first understand how modern electronic financial exchanges operate under the hood:

—
Order Book: A real-time, ledger listing all open, unexecuted instructions from traders waiting to buy or sell an asset (like Bitcoin). It is the transparent heart of an exchange.
—
Bids (Buyers): Orders placed by traders wanting to purchase an asset. These sit on the bottom half of the ledger and are ranked from highest price to lowest price.
—
Asks / Offers (Sellers): Orders placed by traders wanting to sell their asset. These sit on the top half of the ledger and are ranked from lowest price to highest price.
—
The Spread: The narrow gap between the highest available buy order (Best Bid) and the lowest available sell order (Best Ask). No trade happens unless someone crosses this gap.
—
Market Liquidity & Depth: The raw amount of volume (number of coins) sitting in the book at various price levels. Deep books require massive cash to move the price; shallow books crash or spike easily.


The Engineering Challenge: Data Drift

Cryptocurrency exchanges handle billions of updates a second. To save network bandwidth, Binance does not broadcast the full order book every millisecond. Instead, they require developers to engage in a complex multi-step data integration technique:

—
The REST Snapshot: A single heavy, explicit HTTP request that fetches a fixed snapshot of the entire order book. The problem? It is already outdated the instant it reaches your machine.
—
The WebSocket Diff Stream: A continuous, live stream of tiny delta patches ("Price X changed size to Y"). The problem? If you don't have the baseline snapshot, these changes mean nothing.
If your code misses or misinterprets even a single update message, your local replica suffers from Data Drift—a fatal state where your database drifts away from reality, meaning your mathematical indicators are calculating complete lies.


How It Works Under the Hood

The backend architecture utilizes Python's asynchronous event loops to implement Binance's exact multi-phase local order book management protocol:

—
Phase 1: Buffering: Connect to the live WebSocket API and immediately stream raw update messages into an in-memory queue without processing them yet.
—
Phase 2: Baseline Syncing: Concurrently hit the REST API endpoint to pull the thick historical snapshot.
—
Phase 3: The Sequence Match: Inspect the transaction sequence numbers (Update IDs). Discard all buffered stream messages that are older than the snapshot, identify the exact event that bridges the gap, and fast-forward through the queue.
—
Phase 4: Integrity Loop: Process live updates continuously. Every single packet checks that its internal start ID matches the previous packet's end ID + 1. If a packet drops or a gap is detected, the pipeline automatically tears itself down and restarts.


The Core Metric: Order Book Imbalance (OBI)

Once the local book is perfectly synchronized, the backend calculates Order Book Imbalance (OBI) across all 100 deep layers of the book using the standard quantitative finance formula:

OBI = (Bid Volume - Ask Volume) / (Bid Volume + Ask Volume)
This standardizes market pressure into a clean range between -1.0 and +1.0. A highly positive value indicates a massive pool of buyers propping up prices (buying pressure), while a highly negative value signals an overwhelming wall of sellers threatening to push prices down (selling pressure).


Key System Features

—
State Separation: All data parsing, stitching logic, and quantitative math calculations are hard-isolated on the server-side Python environment. The client's web browser is completely decoupled from exchange traffic.
—
Zero API Credentials Required: Fully operational over public financial market data relays, eliminating safety overheads or private API keys.
—
Event-Driven UI Stream: Establishes a lightweight WebSocket link between backend and frontend, feeding unified UI updates cleanly to prevent browser rendering stutter.
—
Rich UI Terminal Visualization: Implements real-time price ladders, data pipeline step logs, volume divergence bars, and moving line graphs mapping out historical OBI tracking.


Tech Stack & Tools

Built with Python 3.12+ (FastAPI, WebSockets, HTTPX Async Client, Uvicorn ASGI backend) and modern frontend components (Vanilla JS, Tailwind CSS, Chart.js engine). Project environments are controlled natively using the uv package manager for lightning-fast lockfile resolution.
